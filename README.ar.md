# مدار · نظام أتمتة الموارد البشرية

نظام موارد بشرية قيد التطوير. يأتمت الطلبات والموافقات، ويذكّر الموافق ويصعّد عليه إذا تأخر، ويدير إغلاق المسير، ويحسب التعديلات بأثر رجعي، ويطابق البصمة مع الإجازات والاستئذانات، ويستورد الموظفين من Excel. الضوابط الأمنية منفذة ومختبرة داخليًا، ولم يُفحص اختراقيًا من جهة خارجية بعد.

## وش يحل من مشاكل مسؤول الرواتب والـ HR

| المشكلة | الحل في مدار |
|---|---|
| تأخر المسؤولين في الاعتماد | تذكير تلقائي بعد 24 ساعة، وبعد 48 ساعة يتصعّد الطلب لمدير المسؤول. المدد قابلة للتعديل |
| المدير في إجازة والطلبات واقفة | التفويض: المدير يحدد بديلًا لفترة محددة |
| ما أحد يعرف عند مين الطلب واقف | تقرير التأخير: عند مين، من متى، ومتوسط وقت القرار لكل شخص |
| المتابعة اليدوية مع الكل | المهام والتذكيرات والتصعيد كلها آلية |
| طلبات تجي قريب من إغلاق المسير | يوم إغلاق: اللي يجي بعده ينتقل للشهر الجاي تلقائيًا، وقبله بثلاثة أيام كل موافق يوصله تنبيه بقائمة طلباته |
| بيانات ناقصة وقت الإغلاق | صفحة «جاهزية المسير»: طلبات معلقة، غياب بدون قرار، آيبان ناقص، موظفون جدد |
| تأخر التعديلات المالية (ترقية، نقل، راتب، بدل، مكافأة، خصم) | طلب تعديل بتاريخ سريان. لو اعتُمد متأخرًا، الفروقات تنحسب بأثر رجعي وتنضاف للمسير القادم |
| الموظف الجديد يتأخر في دخول المسير | التعيين من فورم أو من ملف Excel أو من قراءة العقد، والراتب ينحسب تناسبيًا من تاريخ المباشرة |
| فروقات بين البصمة والإجازات | استيراد ملف البصمة ومطابقته تلقائيًا. الغياب بدون طلب يوصل للموظف، وإذا ما رفع طلب يوصل لمديره |
| تأخر الموظف في رفع الاستئذان | نوع طلب «استئذان»: ينعتمد فورًا حسب الحد اللي تحدده (افتراضيًا ساعة)، وله حد شهري، ويتطابق مع التأخير في البصمة |
| استفسارات الموظفين المتكررة | البوابة تعرض حالة كل طلب، وإيميل مع كل تحديث، ومساعد ذكي يجاوب |
| مواعيد الإقامات والعقود | تنبيهات قبل 60 و90 يومًا |
| رصيد الإجازات والمرضية | يتجدد تلقائيًا عند ذكرى المباشرة مع ترحيل المتبقي لين حد تحدده، والمرضية بعد 30 يوم تنخصم حسب المادة 117 |
| تعديل يسري في نص الشهر | الأيام قبل السريان بالراتب القديم تلقائيًا (تسوية تناسبية) |
| نقل موظف أو خروج مدير | طلباته المعلقة تتحول للمدير الجديد فورًا مع إيميل ومهمة |
| المخالصة النهائية | تشمل المكافأة، الإجازات، راتب الأيام اللي ما انصرفت، والإضافات المعلقة، ناقص السلف |
| تأخر رفع حماية الأجور | ملف Excel أو CSV جاهز، ومهمة بموعد نهائي، وتصعيد إذا تأخر الرفع |

## الصلاحيات وقواعد الطلبات

- **صفحة «الصلاحيات»** (لمدير الموارد البشرية): لكل شخص دور وصلاحيات بالمربعات. مثال: محمد «الرواتب»، وسارة «اعتماد الإجازات».
  - الطلب يروح تلقائيًا لصاحب الصلاحية المناسبة: الإجازة لمن عنده «الإجازات»، والسلفة لمن عنده «الرواتب»، والتعديل لمن عنده «التعديلات».
  - إذا ما فيه أحد عنده الصلاحية، يروح لمدير الموارد البشرية.
  - مدير القسم يعتمد طلبات فريقه بدون أي صلاحية إضافية.
  - ما أحد يعدّل صلاحياته بنفسه، ولازم يبقى مدير موارد بشرية واحد على الأقل.
  - أي تغيير ينسجل، ويوصل لصاحبه إيميل، وتنتهي جلساته المفتوحة.
- **صفحة «قواعد الطلبات»**: لكل نوع طلب:
  - تفعيل الاعتماد التلقائي أو إيقافه.
  - الحد بالأيام أو الساعات (مثال: الإجازة 3 أيام أو أقل تنقبل فورًا).
  - من يعتمد اللي يتجاوز الحد: المدير المباشر، الموارد البشرية، الرواتب.
  - حدود ثابتة ما تتغير من الواجهة: السلفة والاستقالة والتعديلات المالية ما تنقبل تلقائيًا أبدًا، والسلفة والتعديل المالي لازم يمرون على الرواتب.

## الأمان

التفاصيل الكاملة، وكل ثغرة وكيف انسدت، في [SECURITY.md](SECURITY.md). باختصار:

- **الصلاحيات تُفحص في السيرفر** لكل صفحة ولكل أداة في المساعد الذكي، مو بس بإخفاء الأزرار.
- **فصل المهام:** ما أحد يعتمد طلبه، ولا طلبًا رفعه هو، ولا مرحلتين من نفس الطلب.
- **التحقق بخطوتين** إجباري لكل من عنده صلاحيات، والرمز ما ينقبل مرتين.
- **تأكيد الهوية من جديد** قبل العمليات الخطيرة: الصلاحيات، القواعد، الإعدادات، التصدير، إنهاء الخدمة، رموز التفعيل.
- **حد للمحاولات** على الدخول والتحقق والتفعيل والروابط والذكاء الاصطناعي.
- **الجلسة تنتهي** بعد 30 دقيقة خمول، وبحد أقصى 10 ساعات.
- **تشفير رقم الهوية والآيبان** داخل قاعدة البيانات بمفتاح منفصل.
- **سجل تدقيق مختوم بسلسلة بصمات**: أي تعديل أو حذف لسطر قديم ينكشف بأمر `verify-audit`.
- **المسؤول التقني (أنت) ما يشوف البيانات** إلا بإذن مؤقت من مدير الموارد البشرية، للقراءة فقط، وكل صفحة تنسجل.
- **الذكاء الاصطناعي معطّل افتراضيًا**، وما ينرسل له رقم هوية ولا آيبان أبد.

## التشغيل على جهازك (تجربة)

تحتاج Python 3.11 أو أحدث.

```bash
git clone https://github.com/Malhar24-cloud/madar.git
cd madar
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # Windows: copy .env.example .env
# للتجربة على جهازك افتح .env وخلّ REQUIRE_2FA=false (أو خلها true وجرّب التحقق بخطوتين)

flask --app wsgi seed           # 19 موظف وهمي + بصمات + طلبات
flask --app wsgi daily          # الفحص اليومي
flask --app wsgi run --debug    # http://127.0.0.1:5000
```

## سيناريوهات تجربها

1. **التذكير والتصعيد:** شغّل `flask --app wsgi hourly`. لو بغيت تجرب بدون انتظار، غيّر «تذكير الموافق بعد» إلى 0 من صفحة الإعدادات.
2. **إغلاق المسير:** ادخل كمسؤولة رواتب، وافتح الرواتب. بتشوف قائمة «جاهزية المسير» فيها الطلبات المعلقة والبيانات الناقصة.
3. **تعديل بأثر رجعي:**
   - اعتمد مسير الشهر.
   - ادخل كأخصائية توظيف واعمل «طلب تعديل وظيفي أو مالي» بتاريخ سريان من بداية الشهر.
   - اعتمده كمدير موارد بشرية، ثم كمسؤولة رواتب.
   - افتح مسير الشهر الجاي، وبتلقى الفروقات مضافة.
4. **البصمة:** ارفع ملف CSV فيه أعمدة `AC-No.,Name,Time` (مثل تصدير أجهزة ZKTeco). الغياب بدون طلب يطلع في الحضور وفي جاهزية المسير.
5. **استيراد موظفين:**
   - من «استيراد موظفين» نزّل القالب، وعبّه، وارفعه.
   - يطلع لك تقرير بالأخطاء قبل الحفظ.
   - العامل بدون بريد يطلع له رمز تفعيل تطبعه له.
6. **الدعم الفني:**
   - ادخل كمسؤول تقني، وبتشوف حالة النظام بس.
   - من حساب مدير الموارد البشرية، امنحه إذنًا من الإعدادات.
   - ارجع لحساب المسؤول التقني، بيشوف البيانات وبيقرأ بس، وكل شي ينسجل.
7. **التحقق بخطوتين:** خلّ `REQUIRE_2FA=true` في `.env` وادخل كمدير موارد بشرية، وبيطلب منك تسجيل تطبيق المصادقة.

## الأوامر

| الأمر | وش يسوي |
|---|---|
| `flask --app wsgi seed --reset` | بيانات تجريبية |
| `flask --app wsgi daily` | الفحص اليومي: العقود، التجربة، الإقامات، الغياب، إغلاق المسير، حماية الأجور، التعديلات المجدولة |
| `flask --app wsgi hourly` | تذكير الموافقين وتصعيد الطلبات المتأخرة |
| `flask --app wsgi backup` | نسخة احتياطية (SQLite) |
| `flask --app wsgi export file.xlsx` | تصدير كامل لبيانات الشركة |
| `flask --app wsgi create-admin email` | أول حساب مدير موارد بشرية لشركة جديدة |
| `flask --app wsgi create-operator email` | حسابك كمسؤول تقني |
| `flask --app wsgi db upgrade` | تحديث قاعدة البيانات بعد أي تحديث للنظام |
| `flask --app wsgi gen-data-key` | يولّد مفتاح التشفير `DATA_KEY` (مرة وحدة لكل شركة) |
| `flask --app wsgi encrypt-existing` | يشفّر البيانات القديمة، أو يعيد التشفير بعد تدوير المفتاح |
| `flask --app wsgi verify-audit` | يتأكد إن سجل التدقيق ما انعبث فيه |
| `python -m madar.scheduler` | يشغّل الفحص كل ساعة واليومي والنسخ تلقائيًا (بديل cron) |

## النشر لشركة (Docker)

على سيرفر Linux فيه Docker، ويفضّل يكون مستضاف داخل السعودية.

```bash
cp .env.example .env
# عدّل: SECRET_KEY, DATA_KEY, DOMAIN, POSTGRES_PASSWORD, BASE_URL=https://الدومين, MAIL_BACKEND=smtp, MAIL_*, COMPANY_NAME
# DATA_KEY تولّده بـ: docker compose run --rm app flask --app wsgi gen-data-key
docker compose up -d
docker compose exec app flask --app wsgi create-admin hr.manager@company.com
docker compose exec app flask --app wsgi create-operator you@yourdomain.com
```

هذا يشغّل:
- **PostgreSQL** لقاعدة البيانات.
- **التطبيق** على gunicorn.
- **Caddy** يجيب شهادة HTTPS تلقائيًا للدومين.
- **خدمة الجدولة** (التذكير والتصعيد والفحص اليومي).
- **نسخ احتياطي يومي** لقاعدة البيانات في مجلد `backups/`، ويحتفظ بآخر 14 نسخة.

انسخ مجلد النسخ لمكان ثاني خارج السيرفر بشكل دوري.
